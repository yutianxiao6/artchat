# 通用短剧模板制作流程

## 核心原则

这个 skill 用于“开始制作一个视频”的生产阶段。用户可能已经在前文和模型讨论过主题、故事、风格或时长，也可能直接说“做一个视频”。执行时先读取当前对话上下文，再决定是否需要补问信息。

不要一律要求用户提供故事，也不要一律不问。规则是：

1. 用户已经给过的信息，不要重复问。
2. 用户没给、且无法从上下文判断的关键信息，必须先问。
3. 用户给了完整故事，就沿用故事并整理成工作流。
4. 用户只给了主题、类型、产品、情绪或大概方向，就根据需求主动生成故事。
5. 用户只说“开始做/开始制作/按刚才的做”，先从前文提取已知需求；只补问缺失项。

## 开始前必须搞清楚的信息

开始正式生成前，至少要确认这些基础信息：

- 主题/内容方向：做什么视频，或者围绕什么故事、产品、情绪、人物、事件。
- 风格：如写实、古风、赛博、二次元、悬疑、广告感、纪录片感等。
- 总时长：如 15 秒、60 秒、2 分钟、3 分钟、系列多集。
- 画幅：9:16 竖屏或 16:9 横屏。

可选但有用的信息：

- 平台/用途：短视频、广告、带货、剧情号、宣传片、测试片。
- 受众：年轻女性、游戏玩家、企业客户、泛娱乐用户等。
- 必须出现：人物、产品、台词、场景、道具。
- 禁止事项：不能出现的元素、不能用的风格、品牌限制。

### 只问未知信息

如果用户已说“做一个 15 秒的视频”，不要再问时长。

如果用户已说“竖屏短视频”，不要再问画幅。

如果用户前文已讨论“古风复仇短剧”，用户现在只说“开始做”，不要再问主题。

如果缺少多个关键项，一次性简短提问：

```text
开始制作前还差几个关键信息：
1. 主题/内容方向是什么？
2. 想要什么视觉风格？
3. 总时长大概多久？
4. 画幅用 9:16 竖屏还是 16:9 横屏？
```

如果只缺一个，就只问一个：

```text
还差画幅：这条视频用 9:16 竖屏还是 16:9 横屏？
```

不要为了细节无限追问。主题、风格、时长、画幅确认后即可进入制作；其他缺失项可用默认值。

## 默认值

仅在用户没有指定、且该信息不影响关键制作判断时使用默认值：

- 平台：短视频平台。
- 每段时长：15 秒。
- 分段规则：每 15 秒为一个视频段落。
- 输出语言：中文。
- 分镜模式默认：宫格分镜模式。
- 画幅缺失时不能默认，必须问 9:16 或 16:9。
- 时长缺失时不能默认，必须问大概时长。
- 主题缺失时不能默认，必须问做什么内容。
- 风格缺失时不能默认，必须问想要什么风格。

## 分集与分段规则

这是生产拆分的硬规则：

1. 总时长小于等于 15 秒：不分段，只做 1 段，也就是 1 个视频。
2. 总时长大于 15 秒：按每 15 秒 1 段均等拆分；每一段对应一个独立视频。
3. 总时长 2-3 分钟：不要分集，只作为单集处理，再按 15 秒拆段。
4. 总时长超过 3 分钟，或用户明确要求多集：才分集。
5. 分集时一般每集 2-3 分钟；再把每集按 15 秒拆段。
6. 如果用户指定集数，优先尊重用户指定集数，然后把总时长尽量均等分给每集。
7. 如果用户只指定“做系列/多集”但没给总时长，先问总时长或每集时长。

计算方式：

```text
总秒数 = 用户总时长换算成秒
如果 总秒数 <= 15：段数 = 1，不分集
如果 15 < 总秒数 <= 180：集数 = 1，段数 = round_up(总秒数 / 15)
如果 总秒数 > 180：集数 = round_up(总秒数 / 150)，每集约 120-180 秒，每集段数 = round_up(每集秒数 / 15)
```

拆分时如果不能整除，尽量均分；最后一段可以短于 15 秒，但不要长于 15 秒。

## 真实工作流与依赖关系

按 OpenClaw 通用短剧工作流执行，但在本 skill 中不要把“次要人物”作为独立步骤。段内配角如果存在，只作为 `script.segments[].minor_characters` 或 `planCharactersScenes.segments[].minor_characters` 的数据字段，供后续分镜和提示词引用；不单独建立一个“次要人物生成步骤”，也不把它写成必须等待的流程节点。

### 总依赖图

```text
需求补齐
-> 分集/分段计算
-> 分镜模式确认
-> episodePlan?（只有多集才执行）
-> script（生成完整剧本、15秒分段、主要人物、段内人物/场景字段）
-> planCharactersScenes（统一主要人物、每段场景、风格模板；段内配角只作为字段）
-> mainCharacters（主要人物参考图）
-> 每段 scene（段内纯场景图）
-> 每段 planFrames（按分镜模式规划画面）
-> 模式尾部流程
-> videoPrompt（最终视频提示词）
-> review（质量审核）
```

### 全局依赖

```text
需求规格
  ↓
分集/分段计算
  ↓
分镜模式确认
  ↓
episodePlan（仅 episode_count > 1 时需要）
  ↓
script
  ↓
planCharactersScenes
  ↓
mainCharacters
  ↓
进入每段制作
```

说明：

- `script` 依赖 `episodePlan`；如果只有 1 集，`episodePlan` 视为已完成。
- `planCharactersScenes` 依赖 `script`，因为它必须读取完整剧本和分段剧本。
- `mainCharacters` 依赖 `planCharactersScenes`，因为它需要统一后的主要人物设定和风格模板。
- 段内配角不单独成为步骤；它们只从 `script` 或 `planCharactersScenes` 的段落字段里带入。

### 每段基础依赖

每一段都按这个顺序：

```text
当前段 script segment
  + planCharactersScenes 的人物/场景/风格模板
  + mainCharacters 的主要人物参考图
  ↓
scene（生成当前段纯场景图）
  ↓
planFrames（规划当前段分镜/首尾帧/故事模板文字分镜）
  ↓
进入当前模式尾部流程
```

说明：

- `scene` 依赖 `planCharactersScenes`，因为场景名称、描述、纯场景提示词来自人物场景规划。
- `planFrames` 依赖当前段剧本、主要人物设定、场景设定、场景图、风格模板。
- 如果段内有配角，把它当作当前段人物信息的一部分传入 `planFrames`；不要为它生成独立步骤。
- 第 2 段及以后要继承前段连续性：当前段 `scene` 参考前段 `scene`，当前段 `planFrames` 参考前段 `planFrames`。

### 三种模式尾部依赖

宫格分镜模式 `grid`：

```text
planFrames
  ↓
storyboard（生成宫格分镜图）
  ↓
videoPrompt（根据分镜图/分镜文字生成视频提示词）
  ↓
storyTemplate（可选故事板/视觉开发板，依赖 storyboard + videoPrompt）
```

依赖说明：

- `storyboard` 依赖 `planFrames.storyboard.grid_prompts`。
- `videoPrompt` 依赖 `storyboard`，同时读取人物、场景、分镜图、grid_prompts。
- `storyTemplate` 在宫格模式中放在 `videoPrompt` 后面，用于补充故事板或视觉开发板，不是生成视频提示词的前置条件。

首尾帧连续模式 `single`：

```text
planFrames
  ↓
firstFrame
  ↓
singleStoryboard（可选，用户手动插入的中间帧）
  ↓
lastFrame
  ↓
storyTemplate
  ↓
videoPrompt
```

依赖说明：

- `firstFrame` 依赖 `planFrames.first_frame`。
- 每个 `singleStoryboard` 依赖上一张帧图，用来保持视觉连续。
- `lastFrame` 依赖最后一个中间帧；如果没有中间帧，就依赖 `firstFrame`。
- `storyTemplate` 依赖首帧/中间帧/尾帧。
- `videoPrompt` 最后执行，依赖首帧、可选中间帧、尾帧和故事模板。

故事模板模式 `template`：

```text
planFrames
  ↓
storyboard（只生成文字 grid_prompts，不直接出图）
  ↓
storyTemplate（根据文字分镜生成故事模板图/分镜表）
  ↓
videoPrompt（严格根据 storyTemplate 看图说话）
```

依赖说明：

- `storyboard` 在模板模式下是文字分镜节点，只要有 `grid_prompts` 就算完成。
- `storyTemplate` 依赖文字分镜、人物、场景、风格模板。
- `videoPrompt` 必须等 `storyTemplate` 完成后再写；如果有故事模板图，必须严格看图说话。

### 跨段依赖

```text
第1段 scene -> 第2段 scene -> 第3段 scene ...
第1段 planFrames -> 第2段 planFrames -> 第3段 planFrames ...
grid 模式：第1段 storyboard -> 第2段 storyboard -> 第3段 storyboard ...
```

规则：

- 后一段场景要参考前一段场景，避免同一地点反复变样。
- 后一段分镜要参考前一段分镜/尾部画面，保证视觉和动作衔接。
- 宫格分镜模式下，后一段 storyboard 要参考前一段 storyboard 的连续性。
- 视频提示词可以读取全局上下文，但不能跳过本段依赖直接生成。

### 依赖检查表

生成任何节点前先检查：

| 要生成 | 必须已有 |
| --- | --- |
| episodePlan | 需求规格、总情节、多集数量 |
| script | 当前集 plot、风格、类型、段数 |
| planCharactersScenes | 完整剧本、分段剧本、风格、类型 |
| mainCharacters | planCharactersScenes 的主要人物、style_template |
| scene | 当前段场景规划、style_template、前段场景连续性 |
| planFrames | 当前段剧本、主要人物、场景、style_template、前段 planFrames |
| storyboard(grid) | planFrames.storyboard.grid_prompts |
| firstFrame(single) | planFrames.first_frame |
| singleStoryboard(single) | 上一帧图、对应中间帧规划 |
| lastFrame(single) | firstFrame 或最后一个 singleStoryboard、planFrames.last_frame |
| storyTemplate(grid) | storyboard、videoPrompt |
| storyTemplate(single) | firstFrame/singleStoryboard/lastFrame |
| storyTemplate(template) | storyboard 文字 grid_prompts |
| videoPrompt(grid) | storyboard、人物、场景、grid_prompts |
| videoPrompt(single) | firstFrame/singleStoryboard/lastFrame、storyTemplate |
| videoPrompt(template) | storyTemplate 文本或图片 |

## 分镜模式确认

必须先判断适合哪种制作方式，再开始分镜。不要让模型默认使用首尾帧连续模式，除非用户主动安排或明确要求。

### 宫格分镜模式

适合所有流程制作。成本低，速度快，整体可控率一般。

适用：

- 普通剧情短剧。
- 对话、情绪、反转、产品植入。
- 用户没有特别要求首尾帧控制。
- 预算有限或想快速出片。

默认优先选择这个模式。

### 首尾帧连续模式

复杂，需要出很多张图，成本高，但便于精细控制画面。

适用：

- 用户主动要求首尾帧、图生视频、精细控制。
- 明确要控制一个动作从开始到结束。
- 需要严格控制角色位置、构图、动作过渡。

一般不要主动选择这个模式，除非用户明确安排。

### 故事模板模式

适合战斗、打斗、高速运动、复杂动作场景。需要频繁生成图片来控制画面，视频效果完全取决于图片质量；图片质量高时，视频可控率不错。

适用：

- 战斗、打斗、追逐、高速运动。
- 动作变化很快，单纯文字视频提示词容易跑偏。
- 需要用故事板图片作为视频蓝图。
- 需要把每一格画面都先画出来，再让视频提示词“看图说话”。

注意：

- 故事模板模式不是最省钱的模式。
- 它的关键不是文字有多漂亮，而是故事模板图质量足够高。
- 如果故事模板图不准，视频提示词必须先回到故事模板图重做，不能硬写。

## 最终交付格式

如果用户只是让你“开始制作”，并且信息齐全，按以下结构输出：

```text
【1. 需求规格】
【2. 分集/分段计算】
【3. 分镜模式确认】
【4. 依赖关系】
【5. 故事/剧情方案】
【6. 剧本 JSON】
【7. 人物场景规划 JSON】
【8. 每段分镜规划 JSON】
【9. 故事模板/故事板提示词】（按模式需要输出）
【10. 视频提示词 JSON】
【11. 质量审核】
```

如果输出过长，先输出：

```text
【1. 需求规格】
【2. 分集/分段计算】
【3. 分镜模式确认】
【4. 依赖关系】
【5. 完整故事和剧本】
【6. 第1段完整制作包】
```

然后继续生成剩余段落。

## 质量审核

最终交付前按顺序检查：

1. 是否只问了未知信息，没有重复问已知信息。
2. 15 秒是否没有分段。
3. 2-3 分钟是否没有分集。
4. 超过 3 分钟或用户指定多集时，是否每集 2-3 分钟。
5. 是否每 15 秒均等拆成一个视频段落。
6. 分镜模式选择是否符合规则；是否避免主动选择首尾帧连续模式。
7. 是否输出了清晰依赖关系，包括全局依赖、每段依赖和模式尾部依赖。
8. 是否没有把段内配角/`minor_characters` 写成独立制作步骤。
9. 剧本是否按代码结构输出 full_text、main_characters、segments。
10. 人物 description 是否以“【性别：男/女/其他】”开头。
11. 场景是否纯环境，并明确无人物、无人影。
12. 分镜是否以镜头语言开头，避免人物图鉴式描述。
13. 视频提示词是否严格来自分镜、首尾帧或故事模板图。
14. 故事模板模式是否严格“看图说话”，没有瞎编。

## 禁止事项

- 不要因为用户说“开始做”就忽略前文上下文。
- 不要重复询问用户已经给过的信息。
- 不要在主题、风格、时长、画幅缺失时强行开做。
- 不要加入额外的内容分类。
- 不要把段内配角/`minor_characters` 作为独立制作步骤。
- 不要主动选择首尾帧连续模式，除非用户明确安排。
- 不要把 15 秒视频拆成多段。
- 不要把 2-3 分钟视频拆成多集。
- 不要简写代码里的核心提示词规则。
- 不要跳过人物场景规划直接写视频提示词。
- 不要让视频提示词脱离分镜、首尾帧或故事模板图自由发挥。
